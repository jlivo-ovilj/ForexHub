Where it could be tightened

1. Seven separate callers fetch the same 28 quotes. Ticker, Trends, Heat map, Tree map, Scanner, Pullback scanner and Calculator each call /price for the whole watchlist (3 requests each). A single shared quote cache with a 60-second life would cut most of those to zero when you move between tabs.
Saves worker requests and the 2–3 s wait on each tab. Low risk: the data is identical.
2. The calendar is fetched up to three ways. The Calendar tab, the IQ pickers and the briefing each ask the worker for the same weeks. One in-page store (_calAll already exists) could feed all three.
Ask IQ (v24) already reads the shared store rather than fetching.
3. Trends and Heat map are the same numbers in two shapes. Both come from /price: Trends shows % on W/D/4H, Heat map shows pips on D/W/M. One table with a % / pips switch would halve the code and the fetches.
Worth doing when either tab next changes.
4. /briefing is fetched twice — by the Briefing and by the Tree map (for activity sizing). Same fix as #1.
Small.
5. Basket technicals repeat pair technicals. /strength computes ratings on baskets from the same Yahoo bars /tech already pulls per pair. The worker could reuse the per-pair bars.
Worker-only change; saves Yahoo subrequests.
6. AI cost is already shared — identical prompts are cached in KV server-side, so a second device costs nothing. Ask IQ is deliberately uncached (each question is new).
Nothing to do; noted so it isn't "optimised" away.
